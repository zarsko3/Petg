# Create PRD Workflow

## Purpose
Create a comprehensive Product Requirements Document (PRD) that clearly defines the feature scope, requirements, and acceptance criteria.

## Process

### 1. Analyze Requirements
- Review the feature description and goals
- Identify key stakeholders and users
- Understand technical constraints and context
- Consider existing codebase and patterns

### 2. Structure the PRD
Use this template structure:

```markdown
# Product Requirements Document: [Feature Name]

## Overview
Brief description of the feature and its purpose.

## Goals & Objectives
- Primary goal
- Secondary goals
- Success metrics

## User Stories
- As a [user type], I want [goal] so that [benefit]

## Functional Requirements
- Core functionality
- Edge cases
- Error handling

## Non-Functional Requirements
- Performance requirements
- Accessibility requirements
- Security considerations

## Technical Requirements
- Dependencies
- Integration points
- Data requirements

## Acceptance Criteria
- Specific, testable criteria
- Performance benchmarks
- Accessibility standards

## Constraints & Assumptions
- Technical limitations
- Business constraints
- Assumptions made

## Risks & Mitigation
- Potential issues
- Mitigation strategies
```

### 3. Review & Refine
- Ensure clarity and completeness
- Validate against project constraints
- Get stakeholder input if needed

## Output
Save as `/tasks/prd-[feature].md`
